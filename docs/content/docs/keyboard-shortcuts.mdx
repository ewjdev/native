---
title: "Keyboard Shortcuts"
---

The Native SDK can register app-level keyboard shortcuts and deliver them to both Zig and JavaScript. Shortcuts are matched by key plus modifiers and are scoped to the native window that receives the key event. To react while another app has focus, use [global shortcuts](#global-shortcuts).

## Manifest

Declare shortcuts in the app manifest. This example uses ZON:

```zig
.shortcuts = .{
    .{ .id = "command.palette", .key = "p", .modifiers = .{ "primary", "shift" } },
    .{ .id = "reload", .key = "r", .modifiers = .{ "primary" } },
},
```

`primary` maps to Command on macOS and Control on Windows/Linux. Use `command`, `control`, `option` or `alt`, and `shift` when a platform-specific modifier is required.

An app can define up to 64 shortcuts. Shortcut ids can be up to 64 bytes and keys can be up to 32 bytes.

Chromium builds are currently macOS-only. Use the system WebView backend on Linux when an app needs native shortcut events.

## Runtime

Generated runners register shortcuts from `app.json` or `app.zon` automatically. Use `RunOptions.shortcuts` only when an app needs to override the manifest with a list built in Zig.

Apps that construct a runtime directly can pass shortcuts in `Runtime.init`:

```zig
const shortcuts = [_]native_sdk.Shortcut{
    .{ .id = "command.palette", .key = "p", .modifiers = .{ .primary = true, .shift = true } },
};

var runtime = native_sdk.Runtime.init(.{
    .platform = platform,
    .shortcuts = &shortcuts,
});
```

## Events

Zig apps receive `Event.shortcut`:

```zig
fn event(context: *anyopaque, runtime: *Runtime, ev: Event) anyerror!void {
    _ = context;
    _ = runtime;
    switch (ev) {
        .shortcut => |shortcut| {
            if (std.mem.eql(u8, shortcut.id, "command.palette")) {
                // Open palette
            }
        },
        else => {},
    }
}
```

The JavaScript bridge emits a `shortcut` event on `window.zero`:

```ts
window.zero.on("shortcut", (event) => {
  if (event.id === "command.palette") {
    openCommandPalette();
  }
});
```

The event detail includes `id`, `command`, `key`, `windowId`, and `modifiers`. `command` is an alias for `id`.

## Keys

Portable single-character keys are letters, digits, and the unshifted punctuation keys `=`, `-`, `,`, `.`, `/`, `;`, `'`, `[`, `]`, `\`, and `` ` ``. Named keys are `escape`, `enter`, `tab`, `space`, `backspace`, `arrowleft`, `arrowright`, `arrowup`, `arrowdown`, `delete`, `home`, `end`, `pageup`, `pagedown`, `insert`, and `f1` through `f12`.

Single-character keys and text-entry keys (`enter`, `tab`, `space`, and `backspace`) require at least one modifier so shortcuts do not intercept normal typing by default.

## Global shortcuts

A global shortcut fires while any app has focus and reports both the press and the release, so an app can act on a single press (a launcher or command palette) or for as long as the keys are held (push-to-talk, hold-to-peek). Bindings use the same keys and modifiers as app shortcuts, and an app can register up to 16 of them. They are set at runtime, so a preferences screen can let users rebind them.

In a TypeScript core, declare each one from the model with `Sub.globalShortcut(id, binding, arm)`. The shortcut is registered while the model declares it, re-registered when its binding changes, and unregistered when it leaves the set:

```ts
import { asciiBytes, Sub } from "@native-sdk/core";
import { type GlobalShortcutState } from "@native-sdk/core/events";

export type Msg =
  | { readonly kind: "talk"; readonly id: Uint8Array; readonly state: GlobalShortcutState }
  | { readonly kind: "toggle" };

export function subscriptions(model: Model): Sub<Msg> {
  if (!model.enabled) return Sub.none;
  return Sub.globalShortcut("talk", { key: asciiBytes("space"), option: true }, "talk");
}
```

Every report dispatches the named arm with the shortcut's `id` and a `state`:

      <td>The keys went down or came back up. Every press is followed by one release, including when the binding is removed or changed while held.</td>
    </tr>
    <tr>
      <td><code>conflict</code></td>
      <td>The OS or another app already owns the combination.</td>
    </tr>
    <tr>
      <td><code>unsupported</code></td>
      <td>The platform has no global shortcuts (Linux today).</td>
    </tr>
    <tr>
      <td><code>rejected</code></td>
      <td>The binding is invalid: an unknown key, a letter or text-entry key without a modifier, or an id that breaks the command-id rules.</td>
    </tr>

</table>

A binding whose registration failed is never silent: it reports `conflict`, `unsupported`, or `rejected`, and the app can show that next to the setting. Zig cores use the effects channel directly: `fx.setGlobalShortcuts(.{ .key = 1, .shortcuts = &shortcuts, .on_event = Fx.globalShortcutMsg(.hotkey) })` registers or replaces the whole set, `fx.clearGlobalShortcuts(1)` unregisters it, and the Msg arm receives a `native_sdk.EffectGlobalShortcutEvent`.

Reports are journaled like every other effect result, so record/replay reproduces them without touching the OS. On the null platform, Zig tests drive presses and releases with `NullPlatform.pushGlobalShortcut(id, .pressed)` and `.released`, and `claimGlobalShortcut(key, modifiers)` makes a combination answer `conflict`.

On macOS, global shortcuts are Carbon hot keys: they need no Accessibility permission because the app only receives the combinations it registered, never other keystrokes. `primary` is Command. On Windows, `RegisterHotKey` reports the press and the runtime polls the key every 10 ms while it is held to report the release; `primary` is Control and `command` is the Windows key. Linux reports `unsupported`, and `runtime.supports(.global_shortcuts)` answers false there. A global shortcut takes the keys before any window sees them, so it also wins over an app shortcut with the same binding.
